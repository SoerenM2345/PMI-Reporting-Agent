# Dell–EMC Synthetic PMI Corpus (Value Creation Integration Office)

**21 fully populated documents** for testing the PMI Reporting Agent. Every document is filled with
consistent, case-anchored content: no placeholders, no `[...]`, no empty tables.

Two design priorities, in this order:

1. **Internal consistency, absolute.** Every figure comes from one place. Aggregates are *computed*,
   never typed twice, so the SteerCo deck, the tracker, the dashboard and the minutes cannot drift.
   Programmatically audited: **130 checks, 0 failures.**
2. **Case fidelity, as high as the public record allows.** Entities, dates, deal terms, governance
   structure and workstream cut come from the SEC filing and Deloitte's published case study.
   Everything operational is synthetic and labelled as such.

### The transcript / minutes pair (documents 21 and 14)

The transcript is the **source**; the signed minutes are the **derived record**. The pair is the
only place in the corpus where the same event exists at two levels of compression, which makes it
the natural test for meeting-summarisation — and it lines up with the QMSum / AMI direction already
in `MASTER.md`.

Alignment is enforced by the audit, not asserted by the document. Every one of these must hold:

- all four decisions minuted at session 01 (B-01, B-02, B-03, B-06) are spoken in the room, and the
  transcript introduces **no fifth decision** the minutes do not carry;
- all four actions (OP-01 … OP-04) are read back at the end with the same owner and due date;
- all four escalated risks (R-01, R-04, R-06, R-11) are presented with the same likelihood, impact
  and severity as the register;
- every attendee in the minutes speaks or is explicitly accounted for, and the absent member's
  apologies match;
- quorum, agenda approval, deferred items, next-session date and papers deadline agree;
- **the transcript gives no M-07 forecast date** — the chair asks for one and the IT lead refuses to
  give a number he cannot stand behind, which is why action OP-02 exists. This keeps planted
  conflict C2 clean rather than adding a fourth date to it.

Two figures exist only at session-01 vintage and are lower than the W3 values, so the series is
monotonic: secured USD **1,980 m** reported in the pack against USD **402 m** Finance could validate.
That gap is what produces decision B-06 and issue I-03.

## 5. The six planted conflicts

Everything else ties exactly. These six do not, on purpose.

| # | Fact | Values | Correct resolution |
|---|---|---|---|
| **C1** | WS3 IT progress | tracker **59%**, one-pager **66%**, dashboard **53%** | Excel wins (source priority 1) |
| **C2** | M-07 forecast date | roadmap **07.10**, German minutes **14.10**, mail **21.10** | Most recent dated source: the mail, which matches the tracker |
| **C3** | Human Capital lead | role cards name the predecessor, RACI page names the successor | RACI page, which states itself authoritative |
| **C4** | Secured synergy | deck **2,410**, tracker **2,354**, Finance-validated **711** | Validated figure, per decision B-06 |
| **C5** | Risk R-02 severity | RAID log **12 (Medium)**, Teams thread **20 (High)** | **Neither** — flag that the register never received the escalation |
| **C6** | Owner of action OP-01 | signed minutes vs. mail reassignment | Later source, **but flag** that the minutes were never amended |

**C5 and C6 are the ones that matter for the research.** They have no winner. The correct behaviour is
not to pick a value but to surface that the register is stale and the escalation lives only in chat.
That is the coordination-gap claim (H3, H5) made observable.

## 7. How to regenerate

`_generators/case.py` is the single source of truth. Change a milestone date there and every
document that mentions it changes together.

```bash
cd _generators
python3 g2_pptx.py && python3 g2_docx.py && python3 g2_xlsx.py && python3 g2_pdf.py \
     && python3 g2_html.py && python3 g2_img.py && python3 g2_transcript.py
python3 audit.py          # must print FAIL 0
```

`DeloitteMaster.pptx` is the house template the decks are built on.

## 8. Open points

Ordered by how much each one blocks a research result, not by effort.

1. **Two agent repos have diverged, and the image extractor went into the wrong one.**
   `~/Downloads/Projects/PMI/PMI-Reporting-Agent` is the older tree; this repo
   (`GIT/PMI-Reporting_Agent`) is the current, spec-driven one and **already has its own
   `app/extractors/image.py`** written against §5.6 / §21.14 of the spec. The extractor added
   earlier in the older repo is therefore redundant. Decide which tree is canonical and retire
   the other before any more work lands in both.
2. **Weeks 1 and 2 are not generated.** The corpus is the W3 vintage plus the aged backdrop, so
   the agent can be tested on *extraction* and *conflict resolution* but not on **week-over-week
   deltas** — which is what H2 reporting actually claims. Roll `case.py` back two weeks and
   re-run; the generators already support it.
3. **No machine-readable ground-truth key.** The six conflicts and every extractable record can
   only be checked by eye. `case.py` holds everything needed; it needs a JSON export so
   extraction recall and conflict resolution can be *scored* rather than inspected.
4. **No expected-output reference.** The corpus tests what goes in, not what should come out.
   There is no reference SteerCo deck saying "given these 21 files, this is the right answer",
   so report quality cannot be measured at all yet.
5. **No adversarial or negative documents.** Every file is well-formed and on-topic. Missing:
   an off-topic file (does the agent invent PMI structure where there is none?), a scanned
   image-only PDF (OCR path), a corrupted file, and a document in a language neither extractor
   configuration expects.
6. **The two corpora use different workstream cuts.** "Project Atlas" (empty masters) has five
   workstreams, this one has seven. Fine as long as it is deliberate; confusing if not.
7. **`.msg` / `.eml` and `.mpp` remain absent.** Real PMI formats. Note as a limitation in the
   paper, or add.
8. **Tesseract German language pack** (`tesseract-ocr-deu`) is required for the two German
   images; without it stage 1 silently falls back to English-only OCR.
9. **Stale `.~lock.*` files** left by LibreOffice sit in the `Master file data` folder and could
   not be deleted from the sandbox. Remove them by hand.
